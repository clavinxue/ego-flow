# EGO Flow Video

Read [the shared operating contract](../ego-flow-setup/references/operating.md) first. Use the installed EGO guide for API syntax, not another host's browser tools. For character-based work also read the user's supplied character bible; this general plugin does not hardcode a particular brand.

## Resolve a shot

For multiple shots, create a compact shot list: shot ID, action and ending state, references and their roles, Ingredients or Frames, camera, audio, desired aspect ratio/duration, output count, model preference, output filename and approval mode. A single simple shot does not need a mandatory planning detour.

Use Ingredients for identity/object references and Frames for an actual start/end composition when supported by the selected model. Do not upload a multi-view character sheet as the start frame unless a split-screen result is intended. Tell the model which file is which character, product or setting. A reference pack does not authorize uploading every file.

Write one coherent action per short shot, with a stable identity segment and explicit camera/audio cues. Keep exact duration and feature compatibility subject to the actual current UI. Do not assert that camera controls are always absent, or that named Omni/Veo versions, resolutions or duration options always exist. If a model cannot support a requested reference mode or duration, explain and obtain approval for a materially different choice.

## Configure and checkpoint

1. Resume the correct TaskSpace/project and inspect authenticated state.
2. Use observed manual video controls where available; verify the selected generation mode, model, ratio, length, resolution and output count.
3. Attach the authorized references and check their roles. For Frames, verify Start/End placement; never swap silently.
4. Fill the final prompt and inspect the live total credit quote. Report the exact configured shot and cost before Generate in checkpoint mode. A finished/kept prepared tab needs claim/adopt on continuation.
5. With approval, submit once and track the resulting job/card against this shot ID. Do not confuse a previous clip, a queued job or a timeout with a completed new result.

## Inspect and continue

Wait using bounded observations of the actual rendering state. Inspect the completed clip using playback or sampled frames supported by the host, not just a thumbnail, when available. If only a thumbnail can be reviewed, disclose that temporal continuity has not been verified.

For characters, inspect beginning/middle/end for face and costume drift, reference mix-ups, extra limbs, text distortion, eye/mouth changes, contact/occlusion and prop continuity. Follow the user's own character constraints. Before a paid retry or extension, apply the approval/budget rules again.

## Assemble and export

If the user requested assembly and the current UI supports scenes/timeline, add only verified selected clips, confirm shot order, transitions, aspect ratio and audio, then export. Observe controls instead of fabricating editor routes. If unavailable, deliver the individual clips and explain that assembly was not completed. Do not claim the export succeeded before it exists.

Read the live export/download options. Prefer the approved original or no-additional-cost choice, never a permanently assumed free upscale. Save with the documented download event to a new absolute filename. Verify a non-empty media artifact and inspect dimensions/duration when supported; exclude login HTML masquerading as mp4. Report files, settings, actual cost observations and the level of visual/temporal review performed.
